    Likelihoods

    Likelihoods¶

    The top-level component likelihoods contains an array of likelihoods in struct format specifying mappings of distributions and observations. The corresponding distributions and observations are inserted as keys in string format referencing to distributions and observations defined in the respective top-level components, or as numbers for fixed data values. The combination of parameterized distributions \(m_i(\theta)\) with observations \(x_i\) generates a likelihood function

    \[ \begin{aligned} \ensuremath{\mathscr{L}}(\theta) &= \prod_i \text{PDF}(m_i(\theta), x_i), \end{aligned} \]

    where \(\theta\) is the record of the parameters of all distributions of the likelihood, merged by name: a parameter that occurs in several distributions is one and the same parameter.

    A likelihood consists of exactly the terms it lists: one term for each entry of distributions, evaluated on the entry of data at the same position, and one term for each entry of aux_distributions. Nothing else contributes. A likelihood whose data is null is a pure model (see Pure models): its distributions are not paired with anything, so that it has no terms to evaluate until data is supplied. Also then, it comprises nothing but the distributions it lists. In particular, a distribution that is merely referred to elsewhere in the document, for example in the constraints of a HistFactory modifier (see HistFactory), contributes no term unless the likelihood lists it.

    The components of a likelihood struct are:

    • name: custom string
    • distributions: array of strings referencing the considered distributions
    • data: array of the same length as the array of distributions, or null for a pure model (see Pure models). Each entry of the array is either a string referencing a data set, or a number giving a data value in-line (see Data without axes).
    • aux_distributions: (optional) array of strings referencing distributions defined in the top-level component distributions that enter the likelihood without paired data. They can be used to encode constraint terms, regularizers or penalty terms. Their evaluation is described in Distributions without paired data.
    Example: Likelihoods
    "likelihoods":[ 
  { 
    "name":"likelihood1", 
    "distributions":[ 
      "dist1", 
      "dist2", 
      "single_dimensional_dist_1", 
      ... 
    ], 
    "data":         [ 
      "data1", 
      "data2", 
      0, 
      ... 
    ], 
    "aux_distributions" : [ "regularization_term" ] 
  }, 
  ... 
]

    Contribution of a pairing¶

    The following table states what the basic pairings of a distribution \(m\) with a data set contribute to the likelihood.

    Distribution Data Contribution
    non-extended distribution unbinned, \(N\) entries without weights \(\prod_{k=1}^{N} \text{PDF}(m(\theta), x_k)\), the product of the densities at the entries
    extended distribution with expected event count \(\nu(\theta)\) unbinned, \(N\) entries without weights the product above, times one Poisson term \(\text{PoissonPdf}(N, \nu(\theta))\) per data set
    distribution over bin counts, e.g. histfactory_dist binned \(\text{PDF}(m(\theta), \mathbf{n})\), evaluated once with contents as the vector of counts \(\mathbf{n}\)
    distribution with a single variate point, or a number given in-line \(\text{PDF}(m(\theta), x)\) at the given value \(x\)
    combined_dist combined the product over the keys of the contributions of the sub-distributions paired with their sub-data sets, each according to this table

    The variates of a distribution are matched to the axes of the paired data set by name. The variates of a distribution over bin counts are the bin counts themselves and have no names. Such a distribution declares the binning it predicts in its own axes, and these must match the axes of the paired binned data set: the same names in the same order, the same bin edges and, for categorical axes, the same categories in the same order. The entries of contents are then the counts of the bins of the distribution in the order defined in Flattening of Binned Contents.

    Data without axes¶

    A number given in-line in data, or a point data set without axes, supplies the value of the single variate of the paired distribution. Whether a distribution has a single variate that can be determined is at the discretion of the implementation; this standard does not list the types of distributions for which this is the case. An implementation that cannot determine the variate must reject the document. This form is a convenience for hand-written documents; software writing HS\({}^3\) documents should write data sets with axes. The range of the variate follows from Normalization range. The value null for the data component as a whole is not a number given in-line, and this rule does not apply to it (see Pure models).

    Distributions without paired data¶

    A distribution listed in aux_distributions has no paired data. Every name it refers to, including the name in its variate component (e.g. x of a gaussian_dist), takes its value from a fixed axis of the domains in use or from the parameter point in use. A name in the variate component that is neither given by a fixed axis nor marked as const is a free parameter like any other, and subject to the rule in Analyses.

    The variate component still determines what \(\ensuremath{\mathcal{M}}\) integrates over, with the range given by Normalization range: if the variate has a bounded axis in the domains of the analysis, the distribution is truncated to that range; a fixed axis has no range, so that the distribution is normalized over its natural support.

    This standard has no separate concept of a global observable. The observed value of an auxiliary measurement is either a constant parameter of a distribution listed in aux_distributions, as described here, or it is given by a data set: the constraint is then listed in distributions and paired with that data set in data, which supplies both the value and the range.

    Pure models¶

    The component data of a likelihood may be null instead of an array. Such an entry of likelihoods is a pure model and not a likelihood in the statistical sense: it groups distributions, so that an analysis (see Analyses) can refer to them. The typical case is a document that contains a model, but no data set at all. A pure model can be used to generate data, for example toy data or an Asimov data set, but it cannot be evaluated as it is: for any operation on the likelihood, data sets have to be created and paired with the distributions first.

    In a pure model, distributions lists one or more distributions of the model. They are not paired with anything and contribute no term until data is supplied. aux_distributions keeps its meaning: it lists the constraint terms of the model, whose names take their values as described in Distributions without paired data.

    It is the component data as a whole that is null. An entry of the array data must not be null: a likelihood either is a pure model, or it has data for every entry of distributions.

    Example: Pure model
    "likelihoods":[
  {
    "name":"model1",
    "distributions":["channel1_pdf"],
    "data":null,
    "aux_distributions":["gauss_constraint_alpha_1"]
  }
],
"analyses":[
  {
    "name":"analysis1",
    "likelihood":"model1",
    "parameters_of_interest":["param1"],
    "domains":["domain1"]
  }
]

    Backward compatibility. Documents conforming to versions of this standard before 0.3 were in practice written by ROOT, which wrote "data": [0], an array with the number 0 as its only entry, for a model without data. Implementations may read a data component of exactly this form in such documents as null. This applies to no other form: a 0 in an array data with more than one entry is a data value given in-line, also in these documents. In documents conforming to version 0.3 or later, a number in data is always a data value.

    Encoding of auxiliary measurements and global observables is discussed in Auxiliary measurements.
